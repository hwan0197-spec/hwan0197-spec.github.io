인스타그램 광고를 처음 돌릴 때는 광고 이미지와 문구에 신경을 많이 씁니다. 그런데 손님이 광고를 누른 **다음에 보는 화면**, 즉 랜딩페이지가 준비되지 않으면 광고비는 클릭에서 끝나 버립니다.

이 글은 광고 관리자를 열기 전에 랜딩페이지에서 확인할 것들을 순서대로 정리한 체크리스트입니다.

> 메타 정책 관련 내용은 2026년 11월 1일에 [Meta 광고 정책 소개](https://transparency.meta.com/policies/ad-standards/)와 [Meta 스팸 정책](https://transparency.meta.com/policies/community-standards/spam/), [Meta가 노출을 줄이는 콘텐츠 유형](https://transparency.meta.com/features/approach-to-ranking/types-of-content-we-demote/) 문서에서 확인했습니다. 정책은 바뀔 수 있으니 광고 전에 원문을 한 번 더 보세요.

## 왜 메타 광고는 랜딩페이지가 따로 중요할까요?

메타 광고를 보는 손님은 대부분 **검색해서 찾아온 사람이 아닙니다.** 피드를 넘기다 우연히 광고를 보고 눌렀어요. 그래서 페이지가 열리자마자 "아, 아까 그거구나" 하고 이어지지 않으면 금방 뒤로 가기를 누릅니다.

또 메타는 광고 정책에서 **광고에서 홍보한 상품·서비스와 랜딩페이지에서 홍보하는 상품·서비스가 같아야 한다**고 정하고 있습니다. 정책을 어기지 않더라도 품질이 낮은 광고는 성과가 떨어질 수 있다고 안내합니다. ([Meta 광고 정책 소개](https://transparency.meta.com/policies/ad-standards/))

## 1. 광고와 페이지 내용이 같은가요?

가장 먼저, 광고에서 한 말을 페이지 첫 화면에서 **그대로 다시 보여 주는지** 확인하세요.

| 광고에서 말한 것 | 페이지 첫 화면에서 보여야 할 것 |
|---|---|
| "첫 상담 무료" | 같은 표현의 "첫 상담 무료" 문구 |
| 특정 메뉴·상품 사진 | 같은 메뉴·상품 사진이나 설명 |
| "이번 달 예약 가능" | 예약 방법과 신청 버튼 |

광고는 A 상품인데 홈페이지 첫 화면은 가게 전체 소개라면, 손님은 A를 찾느라 스크롤하다가 나갑니다. 광고마다 내용이 다르면 **광고별로 맞는 페이지(또는 맞는 위치)로 바로 보내는 것**이 좋습니다.

## 2. 휴대폰 첫 화면에서 할 일이 보이나요?

인스타그램·페이스북 광고는 대부분 휴대폰으로 봅니다. 휴대폰 첫 화면, 스크롤하기 전 영역에 아래 세 가지가 있는지 보세요.

- [ ] **무엇을 하는 곳인지** 한 줄로 알 수 있는 제목
- [ ] 광고와 이어지는 **사진 한 장**
- [ ] **신청·문의 버튼** (또는 바로 아래에 보이는 버튼)

## 3. 페이지가 빨리, 제대로 열리나요?

메타는 **느리게 열리거나 깨진 사이트, 광고로 뒤덮인 사이트로 가는 링크**를 노출을 줄이는 콘텐츠로 안내하고 있습니다. ([Meta가 노출을 줄이는 콘텐츠 유형](https://transparency.meta.com/features/approach-to-ranking/types-of-content-we-demote/))

- [ ] 광고에 넣을 주소를 휴대폰에서 직접 열어 봤나요? (와이파이를 끄고 데이터로도 한 번)
- [ ] 인스타그램 앱 안에서 링크를 눌러 열어 봤나요? 앱 안에서 열리는 화면은 일반 브라우저와 다르게 보일 수 있습니다.
- [ ] 사진이 너무 커서 첫 화면이 늦게 뜨지는 않나요?
- [ ] 주소가 여러 번 다른 곳으로 넘어가지(리디렉션) 않나요?

속도 점검 방법은 [내 홈페이지 모바일 속도 점검하는 법](/posts/mobile-page-speed-check/)에 자세히 정리해 두었습니다.

## 4. 손님을 불편하게 하는 장치는 없나요?

들어오자마자 화면을 가리는 팝업, 나가려 할 때 뜨는 엉뚱한 팝업은 손님을 쫓아냅니다. 메타 스팸 정책에서도 **잘못 누르게 만드는 화면 구성**이나, 페이지를 떠나려 할 때 관련 없는 팝업을 띄워 붙잡는 방식을 문제로 들고 있습니다. ([Meta 스팸 정책](https://transparency.meta.com/policies/community-standards/spam/))

- [ ] 첫 화면을 가리는 팝업이 없나요?
- [ ] 진짜 기능이 없는 가짜 버튼(누르는 척만 되는 재생 버튼 등)은 없나요?
- [ ] 광고에서 약속하지 않은 내용으로 손님을 넘기지 않나요?

## 5. 신청 버튼과 폼이 실제로 동작하나요?

광고를 켠 뒤에 "폼이 안 보내졌다"는 걸 알게 되면 그동안의 광고비가 아깝습니다.

- [ ] 버튼 문구가 "제출" 대신 "무료 상담 신청하기"처럼 **무엇이 일어나는지** 알려 주나요?
- [ ] 직접 테스트 신청을 해서 시트나 메일로 **실제로 도착**하는지 확인했나요?
- [ ] 신청 후 "접수되었습니다, ○시간 안에 연락드릴게요" 같은 **완료 안내**가 보이나요?
- [ ] 카카오톡 상담 버튼을 쓴다면 휴대폰에서 눌러 채팅창이 열리는지 확인했나요?

## 6. 결과를 잴 준비가 되었나요?

광고를 켠 뒤에 측정 코드를 넣으면 그 전 기간의 결과는 볼 수 없습니다. 아래는 **광고 켜기 전에** 끝내 두세요.

- [ ] 메타 픽셀을 설치하고, 신청이 **성공한 뒤**에 `Lead` 이벤트가 기록되나요?
- [ ] GA4도 함께 설치했나요?
- [ ] 어떤 광고에서 온 손님인지 나눠 보고 싶다면, 광고 단계의 **추적(Tracking) 영역**에서 UTM 같은 URL 매개변수를 넣을 수 있습니다. ([Meta for Developers 문서](https://developers.facebook.com/documentation/ads-commerce/marketing-api/advantage-shopping-campaigns/audience-type-url-parameters))

설치 방법과 코드는 [광고 전에 꼭 설치할 GA4와 메타 픽셀 기초](/posts/ga4-meta-pixel-basics/)에 정리했습니다.

## 광고 켜기 직전 5분 점검표

| 항목 | 확인 방법 |
|---|---|
| 광고–페이지 일치 | 광고 문구와 첫 화면 제목을 나란히 놓고 비교 |
| 휴대폰 첫 화면 | 내 휴대폰으로 열어 스크롤 없이 버튼이 보이는지 |
| 열리는 속도 | 데이터 연결로 열어 보기, 앱 안에서도 열어 보기 |
| 신청 동작 | 테스트 신청 1건 → 도착 확인 → 테스트 데이터 정리 |
| 측정 | 픽셀에 PageView·Lead가 들어오는지 확인 |

## 정리

- 메타 광고 손님은 우연히 들어온 사람이라 **첫 화면에서 광고 내용이 바로 이어져야** 합니다.
- 메타 정책도 **광고와 랜딩페이지의 상품·서비스가 같을 것**을 요구합니다.
- 느리거나 깨진 페이지, 손님을 붙잡는 팝업은 성과와 노출 모두에 불리합니다.
- 신청 폼은 **직접 테스트**하고, 측정 코드는 **광고 켜기 전에** 설치하세요.
- 광고를 시작하기 전 위 5분 점검표 한 장만 확인해도 아까운 광고비를 많이 줄일 수 있습니다.
